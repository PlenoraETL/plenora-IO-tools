# Target con un finding aperto: la build strumentata resta obbligatoria,
# l'esecuzione nello smoke di CI no.
#
# Motivazione: uno smoke che fallisce sempre non è un gate, è rumore — smette
# di essere letto e copre le regressioni nuove. Ogni riga qui è quindi un
# debito dichiarato, non una rimozione: il target continua a compilare sotto
# AddressSanitizer in CI e resta eseguibile in locale
# (`scripts/fuzz-smoke.sh --include-quarantined`) e nella campagna lunga
# `scripts/fuzz-campaign.sh`, che non legge questo file.
#
# Una riga si toglie quando il finding è chiuso a monte, quando è stata presa
# una decisione esplicita sul confine (i finding sulla semantica di accettazione
# dei driver non sono correggibili senza ratifica), oppure quando il finding non
# si riproduce in isolamento.
#
# Quest'ultimo caso non è teorico: un input va eseguito da solo, con la stessa
# build strumentata, prima di finire qui. La campagna lancia tutti i target
# insieme, e `-timeout` misura tempo di parete: sotto pressione di memoria un
# input da decine di millisecondi viene archiviato come timeout. Una riga
# scritta su un finding del genere non è un debito, è rumore travestito da
# debito — e nasconde i difetti veri insieme ai falsi positivi.
#
# Formato: <target> <spazi> <riferimento del finding>
